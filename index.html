Every wallet chain is mirrored to many different chain holders. Each holder keeps a full copy. A holder that was offline catches up from the others automatically, and balances can still be read even if some holders are down.

Under the hood

How a payment works.

  1. 01

    Send

    A signs a send block on their own chain. Their balance goes down and the money is now pending for B.

  2. 02

    Confirm

    The primary chain holder checks the signature and balance and adds the block. It handles one block at a time, so if the same money is spent twice, only the first spend goes through.

  3. 03

    Receive

    B signs an open or receive block on their chain that points to A’s send. B’s balance goes up. No other chain changes.

How cryptography is used.

Your key is made on your phone

The app creates a random 32-byte Ed25519 secret on your phone. It is encrypted with a key derived from your 6-digit PIN (scrypt, then XChaCha20-Poly1305) and stored in the phone’s Keychain or Keystore. It is never sent anywhere.

Your address catches typos

Your address is your public key plus a 4-byte SHA-256 checksum, written in base32 after oe_ed25519_. If a single character is wrong, the checksum fails and the payment is stopped before any money moves.

Every block is hashed and signed

To pay, the app writes the block’s fields in one fixed byte layout and hashes them with SHA-256. That hash is the block’s ID. Your phone then signs the hash with your Ed25519 key.

Holders check everything

Each chain holder rebuilds the bytes, hashes them again and checks the signature against the wallet’s public key. If any field was changed (amount, receiver, memo), the block is rejected. Holders run these checks again every time they restart.

Hashes link the chains

Each block holds the hash of the block before it, so past blocks can’t be changed without breaking every block after them. A receive holds the hash of the send it collects, which links the two chains together.

Not tied to one key type

Every key in a block starts with an algorithm number and its length, and every address names its algorithm (oe_ed25519_ today, for example oe_p256_ later). The sender and receiver each carry their own algorithm, so wallets with different key types can pay each other.

Post-quantum ready

Built to switch signatures without starting over

Ed25519 is the only algorithm switched on today. The block format and network were designed so that post-quantum signatures can be added later without a new chain.

  • Room for big keys. Key lengths are stored in 2 bytes, so keys up to 65,535 bytes fit. Post-quantum public keys are often over a thousand bytes.
  • Same block format. A new algorithm only needs a new ID and its key and signature sizes. ONEEUR-BLOCK-V1 stays the same, and so do existing chains.
  • No mix-ups. A wallet is identified by its algorithm and public key together, so the same key bytes under two algorithms always count as two different wallets.
  • Storage is ready. Holders already name wallet files safely when a post-quantum address is too long for a file name.
  • Safe until switched on. Holders reject blocks with an algorithm they don’t support (unsupported_algorithm), so nothing is accepted before it is ready.
  • Easy to move. Payments between key types already work, so moving your coins to a post-quantum wallet would be an ordinary payment.
